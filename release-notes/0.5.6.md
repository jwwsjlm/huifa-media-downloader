## 压缩与队列性能

- 简单压缩改为“大致目标大小”，CPU / GPU 的正常路径只编码一次，不再为精确体积反复重编码。实际文件可能高于或低于目标，没有固定误差或大小上限保证。
- 优化编码器能力检查、分析线程预算和 GPU 调度。合格的 NVIDIA 路径保持显存帧直通，资源允许时让完整源检查与编码并行；保留完整成品校验和源文件保护，通过全部检查后才发布独立文件。
- 改善大任务库的进度同步、日志写入、批量链接去重与取消响应。合集解析不再占住任务控制锁，工具忙时缓存清理会提示稍后重试。

## 稳定性修复

- 同一数据目录限制一个新版实例，在备份和任务恢复前取得独占锁；停止 MCP 时关闭遗留会话并释放核心资源。
- 修复保存设置时后续输入被旧响应清空，以及登录浏览器状态请求积压、旧响应覆盖关闭结果的问题。
- 网页下载保留中文和其他 Unicode 文件名。上传封面在替换、恢复原图和关闭时释放；缓存清理可回收孤儿图片，并保护已生成、已导出的图片和发布文件。闲置超过 24 小时的临时上传可被缓存清理回收。
- 修复可验证共享时间轴的分离直播音画偏移，保留合并、裁切和片头处理中的对齐；无法安全保留时明确报错，保留已录制源文件。

## 升级说明

- 升级前请完全退出旧版（包括托盘进程），或停止旧容器。旧版 0.5.5 不识别新版目录锁，不能与新版同时使用同一数据目录。
- 旧简单压缩任务重试也采用近似体积策略。并行源检查可能增加峰值内存与线程占用，不承诺通用提速比例。
- 分离直播须能确认共享时钟；自动选择可在满足要求时使用音画合并格式。旧录制缓存缺少原始时间轴、音画时轴不重叠，或视频晚到且要求裁切、去片段或加片头时，会明确拒绝处理；必要时请用音画合并格式重新录制。
- macOS 版仍要求 macOS 15 及以上，使用临时签名且未经 Apple 公证；首次打开可能需要在“系统设置 → 隐私与安全”中允许打开。

## Compression and queue performance

- Simple compression now uses an approximate size target and one normal full encode on CPU or GPU. It no longer repeats encoding to meet an exact size. Output can be larger or smaller, with no fixed error margin or maximum-size guarantee.
- Improved encoder checks, analysis thread budgets and GPU scheduling. Eligible NVIDIA paths keep frames in GPU memory and overlap full source checks with encoding when resources permit. Full output validation and source protection remain; separate output files are published only after all checks pass.
- Improved progress updates, log writing, large-batch deduplication and cancellation. Collection expansion no longer holds the task-control lock, and cache cleanup reports when tools are busy instead of waiting while blocking task controls.

## Reliability fixes

- Only one new-version instance can own a data directory. The lock is acquired before backups and task recovery. Stopping MCP closes abandoned sessions and releases core resources.
- Settings saved by an older response no longer erase newer edits. Sign-in browser status requests no longer accumulate or overwrite a completed close operation.
- Web downloads retain Unicode filenames. Replacing, restoring or closing a cover upload releases its temporary image. Cache cleanup reclaims orphaned images while protecting generated covers, exports and publication files; temporary uploads idle for over 24 hours can be reclaimed.
- Split live captures with a verified shared timeline retain audio/video offsets through merging and supported cuts or cover intros. Unsafe combinations fail explicitly and retain their recorded sources.

## Upgrade notes

- Fully quit the old app, including its tray process, or stop the old container before upgrading. Version 0.5.5 does not recognize the new directory lock and must not share a data directory with the new version while running.
- Retrying an older simple-compression task also uses approximate sizing. Parallel source checks can increase peak memory and thread use; no general speedup percentage is promised.
- Split live streams require a verified common clock. Automatic selection can choose a compatible combined format. Old captures without original timing, non-overlapping timelines, and late-video split captures that require cuts, segment removal or a cover intro are rejected. Record again with a combined format when needed.
- macOS builds still require macOS 15+, use ad-hoc signing and are not Apple-notarized. First launch may require permission under System Settings → Privacy & Security.
