## 下载可靠性与批量处理

- 明确画质、帧率、音轨和字幕必须满足；缺项时由用户调整要求重试，自动方案保持自动选择。
- 混合批量逐链接容错，支持取消解析、识别进度和异常汇总；临时网络错误有限退避重试。
- 不同来源同名时在下载前选择改名、跳过或覆盖，跨来源覆盖二次确认；验证成功后替换，失败或取消保留旧结果。
- 新增“使用当前设置重试”，刷新登录、代理、方案与工具；兼容分片可续传，变更来源或格式时隔离旧分片。
- 新增持久化“优先执行”，影响实际等待队列。

## 直播、磁盘与发布保障

- 直播新增“结束直播并保存”；普通取消不发布，录制停止瞬间尚未落盘的尾部数据可能丢失。
- 加强来源及结果时长、实际分辨率和帧率验证；不默认逐帧解码全视频。
- 下载前检查相关磁盘容量；成功后清理中间文件，暂停与失败保留恢复数据；设置页提供容量和安全缓存清理。
- 版本检查、组件更新和安装器共用代理；升级与迁移前创建可恢复的数据库和配置备份。
- Windows 登录、Cookie、代理与导航真实回归纳入 CI 和发布门槛。
- 同步中英文界面与 Docker/MCP 工作流说明；MCP 支持新的恢复、优先级和直播保存操作。

## Download reliability

Explicit media requirements now need to be met or changed by the user. Mixed batches continue past individual failures, support cancellation and summarize issues. Filename conflicts prompt before transfer; confirmed replacements preserve old results until validation succeeds. Current-settings retry refreshes credentials, network and tools while isolating incompatible partial files. Queue priority affects real scheduling.

Live capture can stop and save validated recorded data. Successful jobs clean intermediate caches, with volume space checks and safe cache controls. Source/output duration and actual video properties receive additional validation. Update operations share the proxy, upgrades create recoverable configuration/database backups, and native Windows browser regressions gate releases.

Backups exclude media, runtimes, workspaces and browser profiles; follow RESTORE.txt with the app stopped. Batch summaries are kept for the current session. Live data not yet written at the stopping instant may be lost.
