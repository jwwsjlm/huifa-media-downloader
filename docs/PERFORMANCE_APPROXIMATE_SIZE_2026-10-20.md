# 近似体积与压缩流程优化（2026-10-20）

本轮按用户要求，将简单模式的目标体积改为近似值。用户输入、已有任务的 `targetBytes` 与保存格式不变；实际输出可以大于或小于估算值，不再因超出目标而重新编码或拒绝成品。视频压缩仍有损，无法承诺相同画质下达到任意体积。

## 流程变化

- CPU 和 GPU 均执行一次正常视频编码，删除 CPU 的目标体积双遍和所有体积修正重做。驱动容量错误、CUDA 解码失败仍保留原有的有限恢复尝试。
- 删除精确计算保留音轨/字幕封装大小的中间 MKV，使用现有源统计估算视频码率；保留参数范围验证、固定流预算和封装余量。
- 合格 8 位 SDR、无缩放或降帧的 NVIDIA 路径采用 CUDA 帧直通 NVENC，编码期间不再下载到 CPU 做同尺寸滤镜后上传。
- GPU 任务先做短检查用于规划，完整源检查与编码并行；共享线程额度不足时仍会串行。CPU 编码仍先完成完整源分析。
- 完整源检查照常覆盖后段 HDR、隔行、颜色/格式变化、帧数和时间轴，结果还须与初始颜色/HDR 参数一致。任一侧失败会取消并等待另一侧退出，检查通过前不发布输出。
- 保留最终成品完整解码、音轨/字幕包哈希、章节/附件/颜色验证，以及发布前源 SHA 核对和独立结果文件。

## 已完成的验证

回归覆盖输出超过近似目标时只编码一次、没有精确预算或双遍统计文件；覆盖后台检查不覆盖编码进度、源发生变化、晚出现的动态/静态 HDR、隔行和颜色变化。前端明确显示“大致目标大小”和输出可能偏差。

原 4K VP9 素材的 1,000 帧 NVIDIA 短样本：旧的回传滤镜路径与 CUDA 直通路径，视频包载荷、时间戳与 36,586,999 字节输出一致。耗时 9.162 / 9.118 秒，吞吐基本相同；不能声称直通单独带来显著提速。记录：`output/performance-20261020/cuda-direct-frames/validation.json`。

真实 CPU/GPU 多音轨、字幕、附件、章节及高级缩放/降帧验收通过，GPU 输出 2,532,040 字节，对应估算目标 2,570,495 字节。本项是正确性检查，运行期间与编译重叠，耗时不作性能对照。

上一份 [性能报告](PERFORMANCE_2026-10-20.md) 中的 48分59秒对应 `170701` 的严格目标策略，不是本轮近似体积流程的实测耗时。本轮没有承诺按阶段相减得出的整片速度。

观察到总耗时减少约 49.4%，主要来自删除体积重做和重叠源检查。单次编码约 52 秒，吞吐基本相当；新成品保留 3840×2160、50 fps、像素格式、色彩和 AAC 音轨，时长差为 0，源文件 SHA 不变。新包成品超出目标约 3.54% 仍正常完成，验证了近似体积策略。

并行检查会提高峰值资源占用：本样本私有内存峰值约增加 29.7%，不能沿用上一轮“内存下降”的结论。每秒采样可能遗漏短进程；峰值属于整棵桌面进程树，工作集含共享页，进程 IO 也不等于物理磁盘读写。

这是每包一次的顺序观察，文件缓存可能帮助第二次运行；旧包在 12:39:35–12:39:55 UTC 与前端回归的 CPU 负载重叠。不能把该比例推广到整部 39 分钟原片。机器可读记录与原始目录见 `output/performance-20261020/approximate-size-120s/comparison.json`。
