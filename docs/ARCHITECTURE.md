# 架构决策

本文记录汇发媒体下载器已确认的架构约束。它用于约束后续 Qt/QML 重构，避免把界面问题扩大为不必要的下载核心、数据或发布链路重写。

**状态：已确认；源码层接缝已落地（静态核对），运行验收待明确授权，2026-09-19。**

本文件区分已确认的约束、已落地的接缝和仍需实际验收的项目。当前未运行测试、程序、构建或发布。

## 已确认的决策

### 1. 保留 Python 核心，Qt/QML 负责界面

- Python 保留下载、解析、转码、发布、更新、任务恢复和持久化逻辑。
- PySide6 与 QML 负责窗口、页面、动画、输入和展示模型。
- 本轮不把下载核心迁移到 Rust 或 C++，也不以 QML 重写业务逻辑。

这样可以把 UI 重构限制在展示层，继续复用已验证的 yt-dlp、FFmpeg、SQLite 和更新链路。

### 2. 不使用虚表，明确完整列表的性能目标

- 下载任务、已完成媒体和合集选择保持完整 QML `Repeater`，不改成虚表或隐式“加载更多”。
- 首个性能目标是同时展示 **1,000 条任务** 或 **2,000 条合集项目**；搜索、展开卡片和常规下载进度更新仍应可操作。
- 筛选后的模型只向 QML 暴露匹配结果，不保留全部未匹配卡片、封面请求和隐藏绑定。

这个目标是当前实现的上限约束，不承诺无限量完整渲染。若实际使用量超过它，再单独讨论归档或数据组织方式，不能悄悄把界面改成分页或虚表。

### 3. SQLite 是任务真相源，目录扫描只导入历史媒体

- `data/app.db` 是可执行下载、合集和发布任务状态的唯一真相源。
- `data/config.ini` 仅保存设置，不承担任务状态。
- 更换便携目录后扫描下载目录时，只导入已存在的媒体为“本地历史”。
- 文件系统本身不能恢复未完成下载、断点、格式选择、Cookie 或 worker 状态；这些信息缺失时不猜测创建可恢复任务。

因此，用户迁移便携版时应随程序一起保留 `data/`；媒体扫描是恢复可管理历史的补充，不是下载任务恢复机制。

### 4. 发布范围固定为 Windows x64

- 支持 Windows 10/11 x64。
- 同时交付便携包和安装包。
- 安装包使用 NSIS 提供目录选择页，内部 Velopack MSI 负责文件安装、升级和卸载登记。
- 不在当前重构范围内增加 macOS、Linux、Electron 或独立 Rust/C++ 发行链路。

这让 Qt、Python、FFmpeg、Velopack 和安装器可以围绕单一平台稳定交付。

## 模块与接缝

下列结构复用现有目录，避免新增只会转发调用的浅层模块：

| 模块 | 接缝与职责 |
| --- | --- |
| `app/core` | 下载、解析、转换、发布、更新等业务模块；其 Interface 是命令和领域状态变化，不依赖 QML。 |
| `app/storage` | SQLite 与安全存储 Adapter；负责数据读写、备份和恢复，不把数据库细节暴露给 QML。 |
| `app/adapters`、`app/integrations` | yt-dlp、FFmpeg、发布平台等外部 Adapter；外部工具或平台变化收敛在这里。 |
| `app/presentation` | QML 接缝：`AppBridge`、模型和工作流把核心状态转换为 UI 可消费的数据，并在 UI 线程发出更新。 |
| `app/qml` | 视觉和交互模块；只保存页面级、短生命周期 UI 状态，不直接读数据库、控制 worker 或调用外部程序。 |

核心规则是让复杂性停留在深模块内部：QML 调用少量明确的 Presentation Interface，不能绕过它直接触碰存储或外部 Adapter。

## 已落地的接缝

- `QmlShell` 只向 QML 注册 `appBridge`；运行时、数据库、worker 和外部工具 Adapter 均保持私有。
- 正式入口 `app/main.py` 只创建 `ApplicationRuntime` 与 `QmlShell`，不导入或实例化 `app/ui/MainWindow`。
- `AppBridge` 是 QML 唯一的根 Interface；其 Qt Slot 处理跨页面用户命令，公开的 Presentation 模型可处理本页筛选、排序、草稿编辑等局部交互。QML 不持有业务运行时对象。
- `app/presentation` 不再依赖冻结的 `app/ui` 路径。可复用的文本、发行计划、诊断、数据库恢复提示与启动配置已归入 `app/presentation` 或 `app/core`。
- `app/ui` 仅保留旧 Widgets 兼容实现和必要的兼容导入；不得在其中新增功能，待 QML 手工验收后再删除。
- 冻结 Widgets 的任务和合集状态变更只能调用 `DownloadService` 命令；运行中的 worker 由服务取消并在退出后统一清理，兼容页面不能直接改任务内存、内存队列或 SQLite。
- 任务数据库丢失时等待下载、发布和合集探测（含排队请求）后台使用者结束，再清理旧内存任务缓存和发布待重试结果并切换到替换 SQLite；保留 runtime 引用但已停止的线程仍视为后台使用者，直到其 Qt 回调完成。所有受影响的 QML 列表模型在同一个 Qt 重置窗口内更换数据源并清空旧行。缓存清理或模型刷新暂时失败时，既有监控定时器会在后台使用者结束后重试，且不放开持久化；只有模型刷新成功后，关闭流程才允许向替换库持久化状态，避免旧内存状态污染新的 SQLite 真相源。替换成功会在 QML 显示明确提示。
- 数据库替换同时清除失效的合集与格式选择状态；其 QML 弹层通过既有模型通知关闭，不得继续指向已经清空的任务记录。
- 数据库模式不兼容时也会隔离原始文件及其 WAL 边车文件，再创建新库并提示；当前不假装执行不存在的自动迁移。
- 数据库依赖切换由 `ApplicationRuntime` 统一完成，QML 与冻结 Widgets 生命周期控制器不再分别改写各服务的数据库引用。
- 合集探测条目和选择状态经 `DownloadService` 写入 SQLite；Presentation 模型只读取筛选结果并发出用户命令，失效的合集父任务不会留下孤立条目。
- 合集物化的父任务状态与批次偏移经 `DownloadService` 原子持久化；SQLite 写入失败会恢复内存状态并重排该批次，不能让内存进度领先于任务真相源。
- 重新开始任务时的 Cookie 来源会由 `DownloadService` 原子更新到对应任务树；重试失败且尚未物化子项的合集，也由服务清除错误并切回解析状态。
- 下载核心、工具路径与封面转换运行时设置由 `DownloadService` 归一化应用；QML Settings 只保存配置并请求该服务更新。
- 关闭时的下载状态转换也经 `DownloadService` 的原子批量持久化处理，Presentation 不直接改任务后写数据库。
- QML 模型保留完整的筛选结果；任务、已完成媒体和发布队列模型只计算当前 QML 请求的角色值，避免每次角色读取都构造整张卡片的数据。进度只通知任务卡片实际绑定的角色；造成排序或活动分组变化时只移动并刷新对应任务卡片，不把位置变化误报为任务数量变化。合集信号用有界合并计时器驱动同步，默认顺序的流式新增只读取并插入数据库尾部；发现已存条目数减少时回退完整同步。未变化的筛选结果不重建卡片。筛选以增量增删保留仍匹配的卡片；排序或后台状态变化改变共有行顺序时仍安全地整体同步。已加载媒体和发布队列的单条发布状态会就地更新；批量完成或无法定位的状态变化才合并刷新媒体目录，不改为分页或虚表。
- 发布工作流只响应版本 tag；构建脚本只接受 `win-x64`，NSIS 安装向导显式提供目录选择页，再把所选路径交给 Velopack MSI。
- 用户可见名称和新安装版默认下载目录统一为 `HuifaMediaDownloader`；Velopack 安装版仍沿用历史持久数据目录，确保已有设置与任务数据库能原地升级。

### 静态核对（非运行验收）

- `QmlShell` 当前只注册 `appBridge`；QML 未导入 Python 业务模块，也未直接访问 SQLite、worker 或外部工具。
- QML 中的 `appBridge.*` 调用均对应 `AppBridge` 的公开属性或 Qt Slot；没有第二个运行时上下文对象可供页面绕过 Presentation Interface。
- 下载任务、已完成媒体、发布队列和合集选择均以完整 QML `Repeater` 呈现；仅组合框下拉框使用 `ListView`。
- 当前 `app/ui` 兼容路径没有直接调用任务或合集的 SQLite 写入接口；其状态命令继续经 `DownloadService`。
- `DownloadTask` 的创建与任务状态字段写入收敛在 `DownloadService`；Presentation 与冻结 Widgets 只读取状态或发出服务命令。
- QML 与冻结 Widgets 的合集工作流均复用 `app/presentation/collection_probe_coordinator.py`；探测回调的存储或完成错误统一收口到失败状态，并请求 worker 停止。
- Presentation 的后台服务信号均连接到具备 QObject 线程归属的 Slot；没有以 Python lambda 承接跨线程状态更新。
- GitHub Release 工作流只匹配 `v<semver>` tag，发布脚本固定 `win-x64`，NSIS 向导包含安装目录选择页。
- 上述为源码静态核对，不能替代下载、恢复、安装、升级或性能的实际验收。

### QML Interface

| 类别 | 约束 |
| --- | --- |
| 展示状态 | `AppBridge` 的属性与 QObject 模型；模型只暴露当前筛选后的数据。 |
| 用户命令 | 跨页面命令调用 `AppBridge` Slot；页面局部筛选、排序和草稿编辑可调用其公开 Presentation 模型的 Slot，但模型仍只能转发到既有核心服务或工作流。 |
| 生命周期 | `QmlShell` 的 QML 引擎拥有 `AppBridge`；关闭流程经 Presentation 统一协调。 |
| 禁止项 | QML 不直接读 SQLite、不控制 worker、不调用 yt-dlp、FFmpeg 或发布平台。 |

## 实施约束

- UI 修复优先修改共享 QML 控件或 Presentation Interface，避免逐页面复制补丁。
- worker 的进度、完成、失败和取消状态必须经 Presentation 模型更新；QML 不轮询数据库或阻塞等待外部命令。
- 跨线程 worker 信号必须连接到有 QObject 线程归属的 Presentation Slot；不以 Python lambda 承接完成清理后再改 UI 状态。
- 合集探测的 Presentation 回调遇到存储或状态转换错误时必须结束对应协调器状态并请求 worker 停止；SQLite 保持最后一次成功写入的真相，不留下无 worker 的伪“解析中”状态。
- 合集选择只有在物化计划已成功持久化后才确认；首次物化失败时保留选择界面以便重试，后续批次失败会保留该计划并重试。取消时先删除 SQLite 任务记录、再停止探测协调器；删除失败则保留选择界面与错误提示，不能把未持久化的选择伪装为已确认或已取消。
- 新增外部平台或工具时优先新增/修改现有 Adapter，不在页面中写平台专用分支。
- 配置继续落在 `data/config.ini`，私密凭据不得写入数据库、配置、日志或诊断包。
