# 项目查漏补缺记录（2026-10-25）

汇发媒体下载器通过 yt-dlp 下载媒体，通过 FFmpeg 处理、验证和发布文件，桌面、网页和 MCP 共用核心队列与数据。此次按单用户桌面或私人 NAS 的使用方式检查，沿用现有的 3 路解析、3 路普通下载和 1 路直播预算。

基线为 `1634a1d`。本轮确认并处理三项问题；以下结论仅覆盖列出的代码路径和实际执行的检查。

## 必须修复

### 1. 删除未完成任务后，缓存失去管理记录

- **相关代码：**`crates/core/src/lib.rs` 的 `delete_task`，以及 `storage.rs` 的缓存统计和清理。
- **触发与影响：**暂停、失败或取消的任务没有媒体库记录时，选择删除任务但保留媒体，只删除数据库记录和解析检查点，留下分片与处理中间文件。缓存统计与清理按任务记录遍历，因此这些文件之后既不计入缓存大小，也不能通过清理按钮移除。反复下载并删除大文件任务会持续占用磁盘。
- **本次修复：**在任务记录将被彻底删除时，同时删除其受管任务目录和自定义处理目录。已有媒体库条目继续保留恢复所需记录；已导出的媒体及附件不会因“保留媒体”被删除。删除前检查链接、规范化目录，并拒绝清理包含已知成品的目录。
- **证据：**新增 `deleting_unfinished_records_cleans_caches_but_preserves_saved_files`，修复前明确失败于 `deleted task left unreachable source files`；修复后通过。覆盖三种停止状态、默认和自定义处理目录、保留成品、保留无关文件，以及成品位于旧缓存目录时拒绝删除。
- **剩余边界：**此修复阻止新的缓存遗留；没有扫描或删除用户数据中旧版本已经遗留的孤立目录。记录已丢失时，尤其无法可靠找回用户曾指定的外部处理目录。

### 2. 原有重名保护验收会阻断发布检查

- **相关代码：**`crates/core/src/acceptance.rs` 的 `real_filename_conflict_confirmation_rename_and_successful_cache_cleanup`，以及 CI 使用的 `--include-ignored` 验收。
- **触发与影响：**并行解析加入后，任务在等待下载时会创建 `sources/download-checkpoint.json`。旧测试将 `sources` 目录存在直接认定为“未确认重名就下载了媒体”，因此真实工具验收失败，但该场景下原文件并未改变。
- **本次修复：**确认冲突时，只允许缓存目录中存在一个普通的解析检查点文件；任何额外的分片或媒体目录仍使测试失败。保留原文件哈希、确认覆盖、改名、所有权转移和完成后缓存清理的原有检查。
- **证据：**首次真实工具验收稳定报告 `Conflict downloaded media before confirmation`；修正后针对完整场景复测，结果记录于下方验证表。
- **不处理的后果：**常规单元测试会通过，但开启真实媒体验收的 CI/发布流程仍会失败。

## 应修复

### 3. Vitest 测试依赖包含已知中危漏洞

- **相关文件：**`frontend/package.json`、`frontend/package-lock.json`。
- **触发与影响：**`npm audit` 对 Vitest 4.1.11 及其 `@vitest/mocker` 报出两条中危依赖告警，关联未认证 mock 注册注入和 Windows 路径检查绕过。该依赖只用于开发测试，不进入发行程序；本轮没有发现应用生产接口因此暴露。
- **本次修复：**将 Vitest 精确升级至 4.1.12，并由 npm 更新其同版本依赖及校验值，没有升级无关依赖。
- **证据：**升级后 379 项前端测试通过，`npm audit --json` 返回 0 条告警。
- **不处理的后果：**开发环境继续使用已知受影响的测试组件，特别是在启用相关浏览器 mock 服务时。
- **上游公告：**[GHSA-qxg6-89mg-rqv8](https://github.com/advisories/GHSA-qxg6-89mg-rqv8)、[GHSA-xp26-3454-mjgp](https://github.com/advisories/GHSA-xp26-3454-mjgp)。
