# 下载链路与 yt-dlp 更新检查

检查日期：2026-10-16。环境：Windows x64、Node 24.16.0、Deno 2.9.7、FFmpeg/FFprobe N-127511。网络实测使用隔离数据目录，不读取个人浏览器 Cookie，不修改用户现有任务或组件。

## 结论与入口

桌面端在「设置 → 工具与更新」选择 yt-dlp 的官方稳定版或 nightly，再点 yt-dlp 对应的「更新 / 安装」。版本输入留空安装该通道最新版本；填写完整官方 Release 标签可安装指定版本，包括回退。

更新只作用于新加入的任务。已有任务保留其加入时冻结的工具、Cookie 和代理配置，重试不会自动切换版本。需要使用新版本或新身份配置时，保存设置后重新添加原始链接。处理中失败的任务仍可直接重试处理，使用已保存的本地输入。

Docker 端仍随镜像更新组件，不提供桌面组件安装命令。

## 已修复

| 问题 | 现在的行为 |
| --- | --- |
| 失败只显示通用 `Tool exited`，不知道哪个工具失败 | 显示可执行文件名、退出码和诊断；视频解析、合集、流下载、字幕下载分别保留操作上下文 |
| 桌面与 HTTP 命令边界只返回最外层错误，丢失原因 | 保留完整错误链后统一脱敏，工具检查也返回底层原因 |
| FFmpeg 启动信息很长，最后的真实错误被截断 | 保留开头操作上下文与末尾诊断，总长最多 2,000 字符 |
| Cookie 参数建议被脱敏成 `[redacted]` | 保留 `--cookies` / `--cookies-from-browser`，继续去除 Cookie 文件名、敏感头与签名 URL 参数 |
| YouTube 任务的来源链接失去 `v=`，复制后无法重建任务 | 仅对明确的 YouTube 域名保留经过校验的公开视频编号；其他查询参数、片段和凭据仍移除 |
| 登录要求、429、403、无格式、缺组件等错误缺少处理步骤 | 中英文界面增加对应指导，并保留原始诊断；说明修改身份或工具后需要新建任务 |
| 组件只支持 GitHub API 的最新稳定版，共享出口 403 限流时更新失败 | yt-dlp 从所选官方 Release 下载二进制与 `SHA2-256SUMS`，不消耗未认证 API 配额；其他组件仍使用原有官方发布查询 |
| 无法选择 nightly / 指定版本 | 共享命令支持 `{name:"yt-dlp", channel:"stable"或"nightly", version:"完整标签或空字符串"}`，桌面界面已接入 |
| 指定过旧版本可能成功安装却无法配合应用 | 先执行版本检查和本地模拟参数检查，兼容性失败时保留当前组件 |

版本和通道在网络请求前验证，不接受任意下载 URL 或第三方仓库。下载体大小受限、SHA-256 校验、原生可执行文件检查、临时目录安装、当前组件指针的原子切换及任务冻结校验继续保留。

## 仍需注意的限制

- 上一轮真实 YouTube 测试受出口 429 / 机器人验证限制，Vimeo 要求登录。没有用个人 Cookie 完成这两个网站的登录态下载；更新 yt-dlp 不能保证消除网站的身份或出口限制。
- 视频与字幕由 yt-dlp 下载，遵循冻结的下载代理和 Cookie；封面及 SponsorBlock 目前由独立 HTTP 客户端请求，未读取该下载代理，封面请求也不复用 yt-dlp Cookie。需要代理或额外认证的附加资源可能导致任务停在下载附加文件阶段，本次未改变这部分网络策略。
- 运行时组件更新直接访问 GitHub，不读取「下载代理」设置；该设置属于视频下载身份。FFmpeg / Deno 更新仍可能受 GitHub API 限流影响。
- SHA-256 校验文件通过官方 GitHub HTTPS 获取，本次没有增加 GPG 签名验证。指定不支持当前应用参数的历史版本会被拒绝；模拟检查不能保证所有站点与所有可选参数的兼容性。
- 未启动 Docker 引擎或重新打包发布桌面安装程序；桌面 Rust 代码已编译并测试，新增界面通过组件交互测试与生产构建验证。
