# 性能审计与优化（2026-10-16）

本次以 `main` 的 `432a326`（v0.2.1）为基线，优先检查桌面使用的共享 React 界面和 Rust 核心。先建立可重复测量，再修改三个高频路径：媒体单条查询、任务进度渲染、工具完整性校验的调度。网页宿主同时完成兼容回归。

原始样本、环境和前后结果保存在 [测量数据](performance/2026-10-16-results.json)。结果只代表本机、下述数据和执行方式。

## 环境与方法

- Windows x64，Intel Core i5-14600KF，20 个逻辑处理器；Rust 1.99.0，Node.js 24.16.0。
- Rust 使用 release 构建，调用真实 `Database`、`App` 和工具函数；1,000 / 10,000 条合成媒体记录放在隔离临时数据库中。
- 查询预热 2 次、取 21 个样本；工具 I/O 预热 1 次、取 7 个样本；工具进程检查和快照预热 1 次、取 5 个样本。工具文件合计 452,989,999 字节，测量使用已预热的文件缓存；首次复制工具不计入已有集合冻结的时间。
- 前端调用真实 reducer 并渲染真实 `App`，使用固定的 1,000 / 10,000 条任务、4 个活动任务及相同事件顺序。reducer 重放 240 次更新，预热 1 次、取 7 个样本；App 重放 60 次更新，预热 1 次、取 5 个样本。
- 前端数字来自 jsdom 和开发版 React，关闭 StrictMode，用于比较相同轨迹的 CPU 开销；不代表 WebView2 帧耗时或 FPS。每个 App 样本仍提交 60 次更新，没有通过丢弃事件减少工作。
- 中位数采用排序后的中间样本，p95 采用 nearest rank。少于 20 个样本时，p95 等于最大样本，应结合原始数据看波动。
- 原生端到端验证使用本地生成的媒体和 loopback HTTP，不访问用户的任务、Cookie 或下载目录，不把公网带宽变化计入优化结果。

## 结果

| --- | --- | ---: | ---: | --- |

| App 默认时间排序，60 次进度更新 | 1,000 条任务 | 92.744 | 61.639 | 耗时减少约 34% |
| App 标题排序及全匹配搜索，60 次进度更新 | 1,000 条任务 | 196.093 | 49.179 | 耗时减少约 75% |
| App 默认时间排序，60 次进度更新 | 10,000 条任务 | 742.676 | 545.193 | 耗时减少约 27% |
| App 标题排序及全匹配搜索，60 次进度更新 | 10,000 条任务 | 1,519.767 | 604.612 | 耗时减少约 60% |

### 1. 媒体查询使用现有索引

`crates/core/src/db.rs` 的 `media_by_id` 和 `media_for_task` 原先调用 `media()`，查询并反序列化所有记录后再查找一条。10,000 条记录时，每个缩略图或媒体文件访问都可能重复这项工作，且全表读取和解析占用同一个数据库连接锁。

现在使用参数化的 `WHERE id=?1` / `WHERE task_id=?1` 查询，复用已有的主键和唯一索引。只取回并解析目标记录，JSON 解析也移到连接锁外；无需数据库迁移。缺失记录仍分别返回原有错误或 `None`。回归测试同时覆盖命中、缺失、修改后的记录和无关记录损坏。

影响路径包括桌面图片协议、网页受控文件下载、封面操作、手动转换及处理发布后的媒体关联。

### 2. 纯进度更新复用任务列表

`frontend/src/App.tsx` 原先把整个 `tasks` 对象作为筛选、排序的依赖。每次 progress、speed 或 ETA 更新都会创建新的字典引用，从而重复扫描、拼接搜索字符串及排序；底部活动计数和任务对应媒体也分别全量扫描。

现在由 reducer 跟踪会影响列表的字段：新增、移除、标题、URL、状态及创建时间。只有这些字段或筛选条件变化时才重建列表；纯进度更新继续更新行和详情。活动计数随任务状态增减，任务对应媒体通过 task ID 索引直接访问，隐藏选择的判断也复用计算结果。

回归覆盖进度期间草稿、光标、滚动节点和隐藏选择的稳定性，以及标题、URL、状态、创建时间变化后的即时筛选排序。另覆盖活动计数的新增、删除、重连恢复，以及媒体的部分更新和重新关联。原有虚拟列表及未变化行的引用保持不变。

### 3. 完整工具校验离开 Tokio 工作线程

`App::task_tool` 原先在 async 调用链内同步读取整个二进制并计算 SHA-256。一个 FFprobe 文件约 169 MB，单次校验约 94–95 ms；探测、转换、字幕及章节处理会多次进入这条路径。

现在通过 `spawn_blocking` 完成相同的文件和摘要校验，相关下载、探测及处理调用显式等待结果。每次使用前仍完整校验字节、冻结目录和 manifest，没有改为仅检查 mtime、大小，也没有缓存成功结果来跳过校验。

单线程运行时的 5 ms 心跳重放中，最大延迟从 127.702 ms 降到 15.496 ms。Windows 定时器和调度本身有粒度限制，这个结果不代表程序提供 5 ms 实时性保证。FFprobe 校验本身仍约 95 ms；收益是释放 Tokio 工作线程，让其他异步操作可以继续运行。

篡改回归进一步使用了相同长度的替换字节，并恢复原修改时间，仍能拒绝该工具；工具升级、重启后的旧任务固定版本、路径越界和工具缺失测试也通过。

## 尚存成本与边界

| 路径 | 基线中位数 | 最终中位数 | 说明 |
| --- | ---: | ---: | --- |
| 已有工具集合冻结 | 490.711 ms | 502.665 ms | 完整摘要校验保留；视为基本不变 |
| FFprobe 工具解析及校验 | 94.376 ms | 95.086 ms | 加入阻塞线程调度后，总校验耗时基本不变 |
| 四个工具版本检查 | 998.666 ms | 994.985 ms | 外部进程启动仍是快照的主要成本 |
| 10,000 条媒体的 core 快照 | 1,025.589 ms | 1,018.723 ms | 包含上述版本检查；不包含宿主传输序列化 |

工具版本检查保留串行执行；并行检查试验没有得到稳定收益，最终代码和上述结果均来自保留串行检查的版本。

前端 reducer 更新一个任务仍会复制整个任务字典，复杂度仍为 O(N)。原始重放数据有所波动，不能把这部分中位数变化归因于消除了字典复制。缓冲事件批处理或分区存储可作为进一步优化的独立工作。

`AddDialog` 仍逐条提交计划，每次提交都进入工具冻结。后端已有批量 URL 接口，但直接合并调用会改变部分失败与重试的处理边界，本次保留现有语义。这里是代码审查发现的候选，不把单次冻结耗时乘以任务数冒充端到端测量。

本地多音轨、字幕、章节、封面验收的单次执行时间为优化前 14.55 s、优化后 6.24 s，均通过。只有各一次、文件缓存和调度状态不同，故仅记录作端到端行为验证，不据此宣称转码或下载吞吐翻倍。本次也未测量生产 WebView2 的绘制、真实用户库的内存峰值或公网下载速度。

## 回归结果

- Rust release：core 26、desktop 4、server 4 个测试通过，包括四条真实媒体端到端用例。性能用例在普通 `--include-ignored` 下通过环境变量门控，不增加基准负担。
- 前端：16 个常规测试通过；6 个性能用例显式运行通过、默认跳过。
- TypeScript 检查、Vite 生产构建、8 个 Node 工具与发布测试通过。
- `cargo fmt --all --check`、`cargo clippy --locked --workspace --all-targets -- -D warnings` 通过。
- 未增加运行时依赖，未改变工具版本或数据库 schema。

## 复现

在仓库根目录运行，先按开发文档准备依赖和 `runtime-tools`。工具也可通过 `HUIFA_TEST_TOOLS` 指定。

```powershell
$env:HUIFA_PERF = '1'
cargo test --locked --release -p huifa-core performance_audit_baseline -- --ignored --nocapture --test-threads=1
npm test --prefix frontend -- src/performance.bench.test.tsx --reporter=verbose
Remove-Item Env:\HUIFA_PERF
```

两套基准输出 `PERF_JSON`，包含每个原始样本和分位数。对比代码版本时保持机器、工具文件、任务轨迹和采样数一致，分开执行基准，避免与编译或其他 CPU 密集操作并行。普通回归命令如下：

```powershell
cargo test --locked --release -p huifa-core -p huifa-server -p huifa-desktop -- --include-ignored --test-threads=1
cargo clippy --locked --workspace --all-targets -- -D warnings
npm run check --prefix frontend
npm test --prefix frontend
npm run build --prefix frontend
node --test tests/runtime-tools.test.mjs tests/rust-release.test.mjs
```
