# 使用指南

## 添加下载

粘贴单个或多个链接，选择画质后加入队列。已知的单视频链接会直接入队，包括带播放列表参数的 YouTube 视频；未知链接先识别类型，真正的合集才显示项目选择。手动格式会打开格式选择界面。

混合批量逐个识别，可取消尚未开始的识别；一个坏链接不会中断其他链接。失败链接会保留，本批结束后汇总需要处理的项目，重启后也可从失败分类查找。

### 画质、音轨与字幕

- 自动最高／最低画质按网站实际提供的格式选择，“最高画质”不代表一定有 4K。明确指定的画质、帧率或音轨缺失时会停止该项，通过“调整要求重试”修改要求，不静默降级。
- 字幕默认关闭。选择语言后人工字幕优先，允许时回退到自动字幕，默认保存为外挂 SRT。
- “无字幕时继续下载”默认开启，缺少所选语言时跳过缺失字幕并继续视频；关闭后才要求所有所选字幕必须存在。
- 每个任务的分片并发默认 4，推荐 6，上限 8；已有合法配置保留。调整该值不会增加同时进行的媒体处理任务数。
- “设置 → 下载与处理 → 视频分析线程数”默认根据主机可用逻辑处理器自动分配，完整分析最多使用 8 个线程，也可手动设为 1–256 的整数。保存后用于后续启动的视频分析，正在运行的分析不受影响；手动线程数计入整体资源预算。Docker 网页显示的是服务端主机的检测结果。
- 已结束的直播回放按普通视频筛选。正在直播、等待开播的来源遵守直播筛选；“全部内容”允许这两类来源，是否等待开播由单独选项控制。

### 剪贴板与保存位置

“剪贴板下载”可手动读取、去重并添加链接。桌面版也可在“设置 → 下载与处理”启用剪贴板自动下载，默认关闭；保存后会检查当前及后续复制的 HTTP/HTTPS 链接，使用当前下载设置，合集与手动格式仍保留确认流程。此功能在应用运行期间生效。

桌面下载目录可在“设置 → 下载与处理 → 下载目录”选择，选定可写目录后立即保存。新建或重新添加的任务使用新目录，已有排队、运行、暂停和处理任务保留原目录，已有文件不会搬动。Docker 通过 `./downloads:/downloads` 挂载配置位置，网页不能选择宿主机目录。

新下载默认保存为 `下载目录／视频标题／视频标题.扩展名`。历史文件和目录不批量改名；自定义文件名模板可在下载设置中配置。

## 压缩与格式转换

### 压缩视频

右键已完成且本地文件可用的视频，选择“压缩视频”。压缩生成独立任务和文件，原视频及原任务记录保留，输出默认是 **HEVC / MKV**。

点击“开始压缩”后加入处理队列并跳转到新任务，源文件校验、完整视频分析和编码进度在任务列表及详情中显示。GPU 压缩会先快速检查，资源允许时让完整源视频分析与编码同时进行；所有检查通过后才发布结果。进度条表示当前阶段的进度；可在任务操作中取消。

自动最多同时处理两项，CPU 重编码保持单路。Windows 的两路 NVIDIA 编码要求至少 8 个逻辑处理器、8 GiB 空闲内存、4 GiB 空闲显存，并通过并发探测；高分辨率、HDR、10 位和资源信息不足时串行处理。全片扫描和磁盘校验分别限流，任务优先级和同优先级入队顺序保持有效。安全的 8 位 SDR、最高 4K 且不缩放或降帧的 NVIDIA 路径可使用硬件解码，先验证像素与时间戳一致，通过后视频帧直接留在显存中编码；失败时保留原编码器并使用软件解码。

| 模式 | 调整内容 | 大小约束 |
| --- | --- | --- |
| 简单 | 目标大小滑块或手动输入，保持原分辨率和帧率 | 按大致目标大小压缩，实际输出可能有偏差 |
| 高级 | 视频码率、原始或更小分辨率、原始或更低帧率 | 显示预计大小，不承诺文件大小上限 |

目标输入接受 `4MB`、`4GB`、`4G`、小数、大小写和空格；裸数字按 MB。MB/GB 使用十进制，MiB/GiB 使用二进制。目标不能超过原文件实际大小，也必须能容纳保留音轨等内容。简单模式不会为体积偏差重复编码。高级码率接受 `8Mbps`、`800Kbps`，裸数字按 Mbps。

两种模式分别保留输入草稿，简单模式不会携带高级模式的缩放或降帧设置。分辨率选项保持比例和横竖方向；原始模式保留分数帧率及可变帧率，主动选择固定帧率会改变 VFR 节奏，只允许降帧。

打开压缩窗口时，按当前视频的格式和尺寸检测编码器；检测到可用 GPU 后默认勾选“GPU 编码加速”，否则使用 CPU 并显示原因。可手动关闭 GPU 加速，本次窗口内切换简单／高级模式会保留选择。修改分辨率等设置后会重新检查所选编码器，不支持时需调整设置或手动改用 CPU。处理时失败会停止，可从任务操作中选择“改用 CPU 重试”，不会自动切换。驱动与 FFmpeg 不兼容时，先尝试在“设置 → 工具与更新”应用兼容版，详见 [组件更新](RUNTIME_UPDATES.md)。

压缩会完整分析源视频，检查输出的完整时长、音轨、字幕、附件、章节和可支持的静态 HDR，并校验源文件未被更改。动态 HDR、透明通道等无法可靠保留的组合检测后会终止任务且不发布结果；检查不因并行编码而省略。macOS 随包的 CPU x265 目前仅支持 8 位，不支持的 10 位/HDR 路径会禁用。视频压缩有损，目标过小不一定能兼顾完整内容和保留特性。

### 格式转换与封面

“转换视频格式”支持 MP4、MKV、MOV 和 WebM，优先直接换封装，必要时重编码；高级选项可指定方式和编码器。原文件保留，结果名使用 `标题 [converted]`，重名时递增编号。

封面工具支持 JPEG 裁剪、留白和基于原图的 AI 编辑。AI 配置可获取服务提供的模型列表，也可手动填写模型 ID；未提交的编辑不自动保存。

## 任务恢复与文件安全

### 暂停、重试和优先级

| 操作或状态 | 行为 |
| --- | --- |
| 继续／普通重试 | 沿用任务原有方案、Cookie、代理和工具快照；复用保存的解析结果和同地址分片 |
| 使用当前设置重试 | 刷新方案、Cookie、代理和工具；兼容的来源和格式可续传，变化后隔离旧分片 |
| 处理失败后重试 | 仍有保存的来源文件时可离线重新处理 |
| 优先执行 | 调整等待中的下载、直播或处理队列并保存优先级，不中断正在运行的任务 |
| 结束直播并保存 | 验证并发布已录制内容；普通取消不发布结果 |

临时超时、断网、429 和服务端错误采用有限次数的退避重试；普通下载断流后尽量续传。登录、权限和明确要求不足需要用户处理。直播停止时尚未落盘的数据可能丢失，暂停后恢复也可能存在时间缺口。

解析和媒体下载独立排队，各最多并行 3 项。下载名额占满时，后续任务仍可获取标题、封面和格式，解析完毕后显示“下载排队”，不提前传输媒体。普通视频的解析结果会保存，暂停或重启后优先使用相同下载地址续传；地址被服务器拒绝时最多重新解析一次。新地址无法确认与旧来源一致时仍隔离旧分片，避免拼接错误内容；旧版本未保存解析结果的任务首次恢复也可能重新下载。

### 重复链接、重名和文件缺失

- 同一来源仍在排队、下载、处理或暂停时，再次添加会定位原任务，不会重复启动。已完成、失败或取消的来源再次添加时复用记录，用本次设置重新下载。
- 不同来源同名时，在媒体传输前选择改名、跳过或覆盖；覆盖需要第二次确认。新结果通过验证后才替换旧结果及受管附件，失败或取消会保留旧文件。旧任务被替换的结果会明确标记。
- 外部删除视频不会删除任务和数据库记录，列表显示“不存在源文件”，依赖源文件的操作暂时禁用；文件恢复后自动恢复可用状态。
- 权限不足或磁盘离线显示“暂时无法访问”。状态检查只针对当前可见行和打开的详情，在进入页面、恢复焦点、手动刷新及定时检查时更新。
- 删除任务时可选择同时删除该任务管理的媒体。该选项记住上次选择，新安装默认不勾选；批量删除也需确认，失败项会保留供重试。

### 空间与校验

开始前检查应用数据盘、处理目录和结果盘空间，未知大小的来源无法预估整段占用。成功后清理下载来源和处理中间文件，保留成品、预览与日志；暂停和失败任务保留恢复文件。“设置 → 磁盘与缓存”可查看剩余容量、清理已完成缓存和无任务引用的旧组件。

非直播来源会检查预期与实际时长，合并／转码后再验证结果时长、所需流和已有哈希。这些检查不等同于逐帧解码，也不能证明网站提供的源本身没有损坏。

## 网站登录与代理

公开内容在没有匹配 Cookie 时匿名解析和下载。需要登录时，进入“设置 → 网络与 Cookie”输入来源网站地址：

| 平台 | 登录方式 |
| --- | --- |
| Windows / Linux 桌面 | 内置浏览器或本机兼容浏览器 |
| macOS 桌面 | 本机 Chrome、Edge 或 Chromium，支持 `/Applications` 和 `~/Applications`；Safari 不用于此流程 |
| Docker / NAS | 一次性远程浏览器，或导入 Netscape Cookie 文件 |

桌面登录期间自动同步 Cookie，关闭前再同步一次，无需手动保存。登录区显示保存状态，新任务按目标域名匹配；手动导入在“其他导入方式”中。同步失败会提示并保留此前的 Cookie，仍允许关闭浏览器。Google 等拒绝内嵌登录的网站可用本机浏览器。

桌面内置浏览器提供地址栏、返回、前进和刷新；省略协议时使用 HTTPS。登录浏览器与下载共用代理，修改后需关闭并重新打开登录窗口；保存设置后重启仍生效。浏览器要求代理地址不包含账号密码，可使用本地代理端口。检查新版、组件安装和桌面安装器更新也使用已保存的代理。

浏览器登录状态在应用数据目录的 `login-browser` 独立配置中保存。一个配置可登录多个网站；删除已保存 Cookie 不等于退出网站账号，需要退出时在网站中操作。浏览器配置同样包含敏感登录信息。Docker 的临时浏览器清理和网络边界见 [Docker 文档](../docker/README.md)。

## 设置保存与界面操作

- **保存设置**：下载参数、语言、主题、通知、代理、AI 配置、剪贴板监控和 FFmpeg 版本策略。
- **各自操作后保存**：下载目录、MCP 开关与自启动、访问密码、Cookie 和浏览器偏好。保存 FFmpeg 策略不会立即更换组件，还需应用版本。
- **保存批次方案**：保存快速选项；首页临时画质、列表筛选、组件安装参数和未提交封面编辑不作为全局设置自动保存。

任务列表默认不选择任务，后台进度更新不会改变选择。Shift 连选、Ctrl 切换、Ctrl+A 选中当前筛选结果，列表标题旁也可全选和批量删除。右键及详情可复制标题、来源；桌面端本地结果存在时可复制含文件名的完整路径。

阶段前的 `2/6` 表示当前主要工序和总工序，完成后隐藏。下载大小显示累计已下载量，总量已知时同时显示，估算值用 `≈` 标记；完成后显示成品实际大小。底部总速度汇总全部下载任务，不受列表筛选影响。

结果画质来自实际媒体信息，详情区分来源和成品。`1080p60` 等简写会将 59.94 fps 显示为 60，详情保留精确帧率；未读到帧率时不推测。完成时间可在“设置 → 外观与封面”自定义，例如 `YYYY-MM-DD HH:mm`，其中 `MM` 是月份、`mm` 是分钟。旧任务没有完成时间记录时留空。

### 日志与反馈

“查看日志”保存工具原始参数、标准输出、错误输出和进度，分页显示并自动刷新，可复制完整日志；旧任务此前未记录的输出无法补回。**日志不脱敏，可能包含 Cookie、认证信息、本地路径和临时媒体地址，分享前请检查。** 原始日志只通过已鉴权的任务日志接口读取，不进入普通快照或 MCP 工具结果。

## 数据、备份与更新

应用标识为 `com.huifa.downloader.rust`。默认数据目录是系统本地数据目录下的 `HuifaDownloaderRust`，默认媒体保存在系统 Downloads 下的同名目录。Windows 安装版和便携版共用这些位置，切换前先关闭另一版本。

Cookie、代理和 AI 密钥在 `credentials` 中以明文保存。旧加密记录首次启动时会迁移，完成后删除旧密钥；迁移完成前保留 `.credentials.key`。备份请保留数据目录、媒体和需要继续恢复的任务文件。

应用版本变化、凭据迁移和安装更新前会在数据目录 `backups` 中创建 SQLite 一致副本、配置／凭据备份、校验清单及 `RESTORE.txt`，备份失败则中止相关迁移或安装。自动备份**不包含媒体、工具快照、任务工作区或浏览器配置**；恢复旧任务仍依赖原文件。恢复前关闭应用或容器，并先保留现有数据副本。

侧栏和“关于”可检查应用更新。Windows 便携版手动解压覆盖程序目录，更新时关闭应用并保留 `tools` 和 `portable.flag`。Docker 更新与命名卷迁移见 [部署说明](../docker/README.md)，不要删除原数据挂载。

## 常见问题

| 问题 | 处理方式 |
| --- | --- |
| Windows 双击后退出 | 查看错误提示中的 `startup-error.log`。无提示时运行 [启动诊断脚本](../scripts/diagnose-windows-startup.ps1)，按提示填写 EXE 路径，检查 WebView2 和生成的报告 |
| macOS 首次打开被拦截 | 确认文件来自本项目发行页，再按 [Apple 官方说明](https://support.apple.com/zh-cn/102445)允许打开；当前包尚未公证，要求 macOS 15+ |
| GPU 编码器不可用 | 查看具体原因，尝试兼容版 FFmpeg、更新驱动或使用 CPU；新版本不代表一定更兼容或更快 |
| 网站仍要求 Cookie | 确认域名、代理和所用任务是否为旧快照。部分接口错误也会被网站提取器报为 Cookie 问题，反复登录不一定解决 |
| 检查更新失败 | 检查网络和保存的代理后重试；失败不会显示“已是最新”。应用版本检查在 API 不可用时会尝试官方发行页跳转 |

Windows 诊断脚本运行方式：`powershell -NoProfile -ExecutionPolicy Bypass -File .\diagnose-windows-startup.ps1`。脚本采集系统、程序、WebView2 版本、退出码及本次错误事件，不读取 Cookie 或业务配置；分享报告前仍请检查内容。

抖音解析目前随应用内置临时的 [yt-dlp 提取器兼容修复](https://github.com/yt-dlp/yt-dlp/pull/17826)，官方 yt-dlp 可执行文件不作修改，也不加载用户插件目录。站点变更可能使解析失效，具体问题请附错误日志反馈。
