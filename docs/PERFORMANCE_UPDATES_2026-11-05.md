# 性能、组件更新与网站支持查询（2026-11-05）

## 性能

- `History::sync` 利用保留事件版本连续的约束，直接跳到未读区间。轮询已追上或仅有少量新事件时，不再过滤全部 2,048 条历史事件；重启、历史缺口、容量和字节淘汰仍要求快照恢复。
- FFmpeg 安装后直接使用 `tools.update` 返回的组件状态，移除前端紧接着的第二次 `tools.check`，每次成功安装少启动 4 个版本查询进程。
- 启动时的上游查询在本地组件检查完成后延迟 3 秒执行，不阻塞任务列表。网站查询等待输入稳定 800 ms，旧结果不会覆盖新输入；查询受既有元数据并发限制及 15 秒进程超时约束。

Windows x64、Rust 1.99.1 release 构建，2,048 条合成历史，每个样本查询 20,000 次，5 个样本取中位数。基准在同一进程比较旧过滤实现与新实现，并断言输出相同。数值包含 JSON 结果构造，不包含 IPC、网络或界面绘制。

| 未读事件 | 原实现中位数 | 新实现中位数 | 局部耗时减少 |
| --- | ---: | ---: | ---: |
| 0 | 13.7786 ms | 2.7643 ms | 79.9% |
| 1 | 18.1629 ms | 6.6850 ms | 63.2% |
| 4 | 28.8578 ms | 16.4707 ms | 42.9% |

这是微基准：单次查询节省约 0.55–0.62 微秒，不代表下载带宽、转码速度或整应用提高相同比例。复现：

```powershell
cargo test --locked --release -p huifa-core state_sync::tests::sync_suffix_benchmark -- --ignored --nocapture
```

## 组件更新

桌面启动后检查 yt-dlp 稳定版及当前 Deno / QuickJS-NG。有更新时在底部提示，进入“工具与更新”查看版本并点击安装。FFmpeg 仅在效率优先策略自动查询上游；兼容优先保留项目锁定构建。保留手动 nightly、指定版本及下载来源入口。

新增 Deno / QuickJS-NG 的上游版本查询及固定发行标签安装，复用既有官方来源、SHA-256、平台架构校验和原子切换。安装失败保留旧工具，已有任务继续使用冻结副本。内置抖音插件随程序版本更新；不自动加载任意外部插件。

真实联网验证在隔离临时数据目录完成，未修改开发目录自带组件或用户数据。已从官方源下载、校验、安装并再次查询：

| 组件 | 安装版本 | 结果 |
| --- | --- | --- |
| yt-dlp | 2026.10.26 | 再次查询无更新，旧快照校验通过 |
| QuickJS-NG | v0.18.0 | 再次查询无更新，旧快照校验通过 |
| Deno | v2.9.8 | 再次查询无更新，旧快照校验通过 |

复现：`cargo test --locked -p huifa-core tools::tests::real_upstream_runtime_updates -- --ignored --nocapture`。此测试访问官方上游并下载组件。

## 网站支持查询

“新建下载”新增查询入口，允许输入域名或具体链接；单条粘贴也自动提示。`sites.check` 调用当前 yt-dlp 的 `--list-extractors`，使用同一份内置抖音插件，只进行本地 URL 模式匹配。

结果区分专用解析器、已标记失效的解析器、通用解析，以及仅凭域名无法确认。不会把“没有专用解析器”等同于绝对不能下载，也不会拦截直链或嵌入媒体。下载遇到 `Unsupported URL` 时有独立中文提示。批量输入仍走既有流程，不以一个链接的查询结果代表整个批次。

真实运行验证覆盖 YouTube、B 站、抖音、未知域名和视频直链。界面检查使用本地模拟数据验证自动提示、查询弹窗、更新入口及点击安装后的状态；未通过浏览器执行真实下载安装。

## v0.5.9 发布流水线

- 桌面仅产出可执行程序实际使用的 Rust 库，不再同时链接未使用的静态库与动态库；发行优化参数保持原值。
- Windows 登录验证接受已检查的前端产物，缺少 `dist/index.html` 会直接失败。本地未指定参数时仍检查类型并构建前端。
- 前端生产构建已包含 TypeScript 检查，移除工作流中紧邻的重复检查；压缩后的桌面发行包关闭 artifact 二次压缩。
- 测试失败后也保留已编译的依赖缓存，减少单项失败修复后的重复编译；失败仍阻止发布。
- 首轮 Windows CI 发现 yt-dlp 的解析器列表包含本地编码字节。网站查询现复用现有 `run_limited_text`，保留字节上限、超时和进程监督；结构化元数据继续严格校验 UTF-8。
- macOS Intel 队列验收发现等待处理状态先于下载许可释放。现在下载成功后先释放许可，再持久化和发布等待处理状态。
