# 组件更新

[返回首页](../README.md) · [使用指南](USAGE.md) · [Docker 部署](../docker/README.md)

在“设置 → 工具与更新”查看当前组件版本、系统架构和对应安装包。检查版本只查询信息；应用组件才会下载、校验并切换文件。失败会保留当前组件，不会显示“已是最新”。

桌面包已附带运行工具，无需为了开始下载另行安装。Docker 允许查询组件版本，但组件更换需要[更新镜像并重建容器](../docker/README.md#update-and-preserve-data)。

## FFmpeg：选择兼容或较新构建

FFmpeg 和 FFprobe 必须成对使用。版本策略决定桌面端“应用 FFmpeg 版本”所选的构建：

| 版本策略 | 标签留空时 | 适合的情况 |
| --- | --- | --- |
| 兼容优先（默认） | 使用项目锁定并校验过的推荐构建，无需查询 GitHub Release API | 日常使用，或新构建与驱动不兼容时 |
| 效率优先 | 查询当前平台上游仓库的最新构建 | 尝试较新的编码器和硬件支持；不保证更快 |

需要固定版本时，在版本输入框填写对应平台上游仓库的**完整发行标签**。程序会查询该标签并核对返回值，不接受任意下载 URL 或其他仓库。标签是本次安装参数，不会保存为全局设置。

操作顺序：

1. 选择版本策略，点击“保存设置”。
2. 可先查询可用版本，核对来源、标签和当前安装情况。
3. 在桌面端点击“应用 FFmpeg 版本”，等待成对校验和切换完成。

保存策略不会立即替换组件。“可应用”按所选构建与本地记录是否一致判断，允许切回较旧的兼容构建，不按版本号大小禁止降级。

下载后会验证 SHA-256、当前平台和架构、FFmpeg/FFprobe 版本一致性、必需编码器及 CPU HEVC 初始化能力。默认兼容构建的校验值来自项目锁文件；较新或指定标签的构建使用上游 Release 的摘要或同次发行的官方校验文件。缺少可信校验值就停止安装，全部通过后才切换当前组件。

FFmpeg 不使用下方 yt-dlp 的第三方 CDN。效率策略和指定标签依赖上游 Release API；遇到 403、429、连接失败或缺少对应资产时会明确报错，不会擅自改装其他标签。兼容策略留空不依赖该 API，但仍需能下载锁定资产。

新 FFmpeg 不代表所有 GPU 都可用，具体编码路径仍按当前视频实际检测。macOS 随包 CPU x265 的 8 位限制和压缩保留条件见 [使用指南](USAGE.md#压缩与格式转换)。

## yt-dlp：稳定版、nightly 与下载来源

选择官方稳定版或 nightly 通道后，点击“检查 yt-dlp 更新”。程序通过官方发行页跳转查询最新标签，显示本地版本、远端版本及是否可更新；本地比所选通道新时会明确说明。

桌面安装可选择以下来源。这些选项仅适用于 yt-dlp：

| 来源 | 行为 |
| --- | --- |
| 自动 | 先从 GitHub 下载；连接失败、HTTP 错误、超时或校验失败后改用 `ghfast.top`，首次直连最多等待 30 秒 |
| GitHub 直连 | 只访问官方安装包 |
| 第三方 CDN | 通过 `ghfast.top` 中转安装包 |

版本输入留空时先解析所选通道的最新标签，再下载固定标签对应的安装包；填写完整标签则下载该版本。安装包随系统和架构选择，不尝试安装其他架构。

SHA-256 校验文件始终通过官方 GitHub HTTPS 获取，不从第三方 CDN 获取。CDN 缓存了错误版本或文件损坏时无法通过校验；官方校验文件不可访问时也会停止安装。文件的原生格式、版本和必需参数兼容性通过检查后才切换组件。

第三方中转只接收公开安装包 URL，不接收下载任务的 Cookie、代理凭据或个人媒体 URL。其可用性和速度取决于服务及当前网络。官方包和通道说明见 [yt-dlp Release files](https://github.com/yt-dlp/yt-dlp#release-files) 与 [Update](https://github.com/yt-dlp/yt-dlp#update)。

## 已有任务会使用哪个版本

| 任务操作 | 使用的工具 |
| --- | --- |
| 已有任务继续、普通重试或离线处理重试 | 创建任务时冻结的工具副本 |
| 使用当前设置重试、重新添加原链接 | 当前组件，连同本次方案、Cookie 和代理重新保存 |
| 新建本地视频压缩任务 | 当前 FFmpeg/FFprobe |

升级应用、容器或组件不会替换已有任务的冻结副本。要让旧任务使用新组件，选择“使用当前设置重试”或重新添加原链接；恢复旧任务时仍需保留其工具快照和媒体输入。

## 排查更新失败

- 检查网络与“网络与 Cookie”中已保存的代理；组件查询和安装使用该代理。
- 核对系统、架构、通道和完整标签。FFmpeg 的标签必须属于当前平台所用上游仓库。
- GitHub API 限流与官方资产无法下载是不同问题。yt-dlp 版本查询使用发布页跳转；FFmpeg 效率策略和指定标签仍可能受 API 限制。
- 安装失败时保留当前工具，修复原因后重试。GPU 编码失败可另行选择“改用 CPU 重试”，不会自动切换编码器。

早期下载链路与 CDN 实施记录见 [2026-10-16 下载链路检查](DOWNLOAD_CHAIN_AUDIT_2026-10-16.md)；其中的测试版本和平台范围仅代表当时记录。
